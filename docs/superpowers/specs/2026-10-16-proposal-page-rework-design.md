## 1. Goal

The proposal page is "our main customer-facing artifact that's meant to make the homeowner feel special". It walks the homeowner from the people who visited, through proof, to exactly what will be done, what it costs and how to pay, and then to signing. It is mobile-first and stays crisp on tablet and laptop, because reps present it live in the home. The same page lets a rep send the proposal, read the homeowner's funding choice and run the agreement without leaving it. Internal numbers never reach the homeowner.

## 3. Page content and sources

Each chapter names its data. Company facts come only from `src/shared/constants/company/` or an existing typed constant.

- **Top bar:** `proposal.label`; the customer name (agents); the Cockpit button behind `can('update','Proposal')`; `ThemeToggleButton`; the menu, with the PDF URL from `getProposalPdfUrl(proposal.id, proposal.token)` and the owner rep's phone.
- **Overview:** `projectJSON.data.label`, `.timeAllocated` and `.sow`; `proposal.media` (first image); the catalog trade cover (`useConstructionCatalog`); `proposal.customer`; `proposal.meetingReps`; `proposal.meetingScheduledFor`.
- **Contractor:** `reviews` (with `asOf`); `companyInfo`, `license` and `liabilityCoverage`; `CONTRACTOR_COMPARISON_ROWS` and `CONTRACTOR_QUESTIONS`; the company document URLs (`COMPANY_DOCUMENTS`, moved out of the chapter).
- **Results:** `usePortfolioProjects` + `useConstructionCatalog` → `matchPortfolioProjects`; `showroomDisplay.getDetail` for the featured project (prefetched once the match is known) and on tap for a strip card. Pairs come from `project.beforeAfterPairsJSON.pairs`, with `beforeMediaId` and `afterMediaId` resolved against `media.all`.
- **Scope:** `parseSowSection` (LAZY) and the match from Results.
- **Funding:** `toFundingInputs` + `computeFinalTcp`; `buildPricingBreakdown`; `resolveDeposit`, `getCashDownStops` and `isAllCash`; `computePaymentSchedule`; `getFinanceOptions` + `getLoanValues`.
- **Next steps:** `useContractStatus`, `requestToMoveForward`, `CustomerAgeForm`, `proposal.meetingReps`.
- **Cockpit:** the document's proposal; `views.getProposalViews` (count and last view, agents only, never on `getFullView`); `contracts.evaluateEnvelopeContext` / `getContractStatus`; the customer profile read (`customerPipelinesRouter.getCustomerProfile`, prefetched on idle); the action hosts (Proposal, Meeting, Customer).

## 4. Architecture

### 4.1 The document takes its proposal from context

`ProposalDocumentProvider` holds `{ proposal, token, canAct }`. `canAct` = `can('update','Proposal')`, read once at the page root. Chapters never read route params, so a meeting page or Spec G's tab can host the document later.

### 4.2 Layout

## 6. Error handling and edge cases

- **No meeting / no reps / only the system user:** the company card (P10); copy says "our team" everywhere a rep name would go (Next steps step 2, its action lines, the footer, the overview visit line), through one helper with a test; the menu's call action uses the main line; the email signs with the company name once.
- **One rep:** "Your consultant", one row; copy uses one name.
- **No incentives:** parts show only list prices; the whole-project block is omitted.
- **Total mode:** parts show incentives without prices; the subtotal shows only when part incentives moved it.
- **No SOW parts:** Overview's list and Scope show "Scope being finalized."
- **Unparseable SOW:** the HTML fallback.
- **No portfolio match:** fallback projects with "Recent work". **No public projects at all:** Results shows a one-line link into the in-app portfolio, never an empty chapter.
- **Featured project without pairs:** the hero photo, no slider. **Lightbox gallery fails to load:** the card shows "Photos didn't load" and stays tappable to retry.
- **Finance options empty:** the financed block shows the cash line and the fine print only.
- **Price drops after a saved choice:** the cash down is clamped to the new bounds on render and the clamp is saved; an all-cash deal stays all-cash.
- **Debounced saves racing:** only the last value is sent; a pending save flushes on hide.
- **A save refused** (`invalid_cash_down`, offline): a toast, and the local value stays. **`proposal_frozen`:** the card locks with no toast.
- **Frozen proposal:** Funding read-only; Share shows the line; the age is locked with its reason.
- **Customer email missing:** Send disabled with the line; Copy link still works.
- **Profile unreachable** (not found / forbidden): one line replaces the reference rows.
- **Background refetch fails:** the document stays; the error state shows only when there is no proposal.
- **`recordView`:** skipped without a token.
