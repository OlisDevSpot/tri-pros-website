**Scope compiler is REAL, not invented** — it's CASL's first-party DB-integration pattern: `defineAbilitiesFor` → `rulesToAST` (`@casl/ability/extra`, installed 6.8.0) → ucast AST → Drizzle interpreter (+ custom operators) → `where()`. `accessibleBy` (@casl/prisma/mongoose) is this productized; `@ucast/sql` does AST→SQL for Knex/Sequelize/etc (Drizzle not included → we port ~40-line adapter). Custom cross-table operators (`$participatesInMeeting → EXISTS`) are documented first-class. `$` = ucast/mongo operator syntax.

**7 axes** (don't force into one mechanism): 1 verb/capability, 2 row-visibility (compiled→WHERE, server authority), 3 field-masking (static CASL grants + dynamic SQL CASE for phone), 4 per-row action (row-carried field cond, both sides), 5 state-machine transition (verb gate + imperative, NOT a WHERE), 6 create/precursor (parent point-probe), 7 bearer/token principal (ability=null). Hazard: SYSTEM_CONTEXT write-elevation.

**The atom:** `userParticipatesInMeeting` EXISTS on meeting_participants. Meeting/Proposal/Customer/Project visibility all = this atom via a different FK → collapse to ONE operator `$participatesViaMeetingPath{through}`. Manager-role gap (sees all, not omni, not participant) = **THE motivating case** for the whole restructure (spec §1.2/§4.3, catalog line 88). **`manager` is a FORTHCOMING role — NOT yet in `userRoles` enum (`user|homeowner|agent|super-admin|dispatcher`) nor `abilities.ts`.** It was the load-bearing thought-experiment that exposed why a single `visibility(scope)` fn keyed on userId can't produce role-varying predicates on the same subject. Target: conditionless `can('read','Meeting'|'Proposal')` → empty AST → no WHERE → allow-all. Distinct from super-admin (which is omni via `manage all`); manager sees all *meetings/proposals* only. Do NOT flag its absence from code as staleness — it's designed-for, not implemented.
