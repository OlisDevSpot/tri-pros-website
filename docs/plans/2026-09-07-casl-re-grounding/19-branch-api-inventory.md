## 5. Interface facts a caller must know today (five most-called branch primitives)

Per the deep-module test: a deep primitive has a small signature and the invariants live INSIDE it; a shallow one pushes them onto every caller. Each item lists what a caller must know to use it correctly today.

### 5.1 `requireResolvedScope(scope: SQL | null | undefined): SQL | undefined` — `helpers.ts:95` · 41 sites

- **Invariants the caller must hold**: `scope` must come from a ctx whose scope was CONSCIOUSLY set for THIS entity's table (a `ctx.scope` resolved for `meetings` and passed to a `customers` query compiles fine and correlates wrongly — "missing FROM-clause" at best, false-allow at worst). The function cannot check this.
- **Ordering**: a per-entity procedure (D1–D6), `buildUserContext`, a hand-built ctx literal, or `SYSTEM_CONTEXT` must have run first. A bare `agentProcedure` handler passes `null` and gets allow-all silently — the guard only catches `undefined`, which arises from an untyped path, i.e. almost never in TypeScript.
- **Error modes**: throws a generic `Error` (not a `DalError`) on `undefined`; returns `undefined` (= no WHERE) on `null`.
- **Required config**: none — which is the tell: it has no way to know what it is guarding. **Depth: shallow** (3 branches, zero knowledge; every caller carries the real invariant).

### 5.2 `SYSTEM_CONTEXT` (30 sites) / `systemContext(reason)` (1 site) — `types.ts:53, 68`

- **Invariants**: the caller has ALREADY authorized the operation (webhook signature, super-admin gate, or a server-derived id from an authorized read). Nothing in the value records which; only `systemContext` records a `reason`, and only 1 of 31 sites uses it.
- **Ordering**: the authorization must precede the call in the same handler; hooks receiving this ctx must tolerate `session === null` (and 3 hooks USE `session === null` as the "trusted" signal — `meetings/dal/server/crud.ts:34`, `scope.ts:68`, `customer-notes/lib/server-spec.ts:61`).
- **Error modes**: none — it cannot fail, which is the danger (the `voip-campaigns.disqualify` IDOR of 2026-06-04 is the recorded precedent).
- **Required config**: `SystemReason` union (2 variants for 31 sites). **Depth: shallow** (a shared mutable object literal; the invariant is entirely at the call site).

### 5.3 `resolveActorScope(spec, actor): SQL | null` — `resolve-actor-scope.ts:22` · 20 sites

- **Invariants**: (a) the result is a READ scope regardless of what the caller is about to do (update/delete callers must know the read scope is being reused — D-15 later makes this deliberate); (b) for a child spec the own-scope is verb-only, so a child's own-row condition (e.g. `{ authorId }`) is silently dropped (L9 context); (c) `spec.parent.fk` must be a column of `spec.table` (guarded at `:106-117`, throws); (d) custom operators in the rules assume `spec.table` is the subject's table (`inDerivedPipeline` assumes `customers`; `via: 'meetingId'` assumes `proposals`) — not guarded.
- **Ordering**: `interpret.ts` must have been imported so the operator registry is populated (it is, transitively via `compile-scope.ts`), and `abilities.ts` must have built the ability with the matcher (it does).
- **Error modes**: throws on unknown operators, unknown compound nodes, non-column fields, empty pipeline sets, mis-pointed fks; returns `sql\`false\`` for "no rule" — a deny that surfaces as NOT_FOUND, never as an error.
- **Required config**: `spec.caslSubject`, `spec.primaryKey` (default `'id'`), `spec.parent?`, plus the rules in `abilities.ts`. **Depth: medium** — it hides the AST walk and the bridge (good), but leaks the action, the child own-condition drop, and the table-binding assumption to every caller (bad). The 20 callers each re-derive `requireResolvedScope(resolveActorScope(spec, actor))` — a two-call idiom that should be one.

### 5.4 `canAccess(spec, actor, id, action = 'read'): Promise<boolean>` — `resolve-actor-scope.ts:55` · 11 sites

- **Invariants**: for a ROOT spec `action` is honored; for a CHILD spec it is IGNORED (`:62-66`) — a caller probing `mediaFileServerSpec` with `'update'` gets the read answer. `id` must be client-supplied (server-derived ids should not be probed — D-07). The probe is a separate round-trip; callers must not loop it (`scope.ts:64-65` warns; `projects.router/media.router.ts` calls it up to 4× per handler across slots).
- **Ordering**: must precede the write it guards; but nothing ties the probe to the write — the write can still run unscoped (H7 does exactly that with a raw `db.select` after the probe).
- **Error modes**: `false` → caller decides the code (all 11 chose NOT_FOUND — consistent, by convention only). Throws as 5.3.
- **Required config**: as 5.3. **Depth: medium-shallow** — the signature promises an action-aware probe and delivers one only for roots.

### 5.5 `resolveTrpcActorScope(spec, { userId, ability }): SQL | null` and the `<entity>Procedure` template — `resolve-trpc-actor-scope.ts:18` · 8 sites

- **Invariants**: `auth.userId` and `auth.ability` must be the SAME principal that `ctx.actor` already represents (they are rebuilt from `ctx.session.user.id` + `ctx.ability` at every site; nothing prevents a mismatch). The returned scope is for `spec` only; a handler that then calls a DAL for ANOTHER entity with the same `ctx` mis-scopes (this is why H8/H9/G3 re-scope by hand).
- **Ordering**: must be chained after `agentProcedure` (inline `.use()`), never as a shared middleware (the type-narrowing crutch documented in `customers/procedures.ts:11-18`).
- **Error modes**: as 5.3; plus the silent one: forgetting to import the entity procedure and using `agentProcedure` leaves `ctx.scope = null` = allow-all (documented as "Enforced by: convention" in `src/trpc/DOCS.md#base-procedure-types`).
- **Required config**: one `procedures.ts` per entity; one `resolveScope:` per factory leaf. **Depth: shallow** — it is a 1-line adapter whose only job is to convert `{userId, ability}` back into the actor the ctx already holds; the seven copies of its call site exist to satisfy TypeScript inference, not the domain.

(Sixth, briefly: `canSeeUngatedPhone(actor)` · 8 sites — caller must know that a non-`user` actor is unconditionally ungated, and that the client twin disagrees. Depth: shallow but honest — 3 branches, no hidden ordering.)

## 6. What the branch got right (templates)

1. **The adapter core is deep and honest** — `ast.ts` (structural, no `@ucast/core` dependency, node shapes verified against the installed version), `interpret.ts` (fails LOUD on any compound operator other than `and/or/not` and any field operator other than `eq/in` — `:47-48, :71` — "a silently mis-compiled negation is a false-ALLOW leak"), `operators.ts` registry with a two-sided boot assert (`assertRegistryMatchesContract :58`), and the client-bundle split via `operator-names.ts` (a real constraint, documented with the actual failure: `Module not found: Can't resolve 'fs'`). D-01 already rules this canonical; §1 A5–A12, A16–A19 all KEEP. This is the template for "one small surface, invariants inside".
2. **`fkColumn` guard** (`resolve-actor-scope.ts:106-117`) — turns a mis-pointed `parent.fk` (which would emit a self-correlated wrong-join that passes every row) into a loud throw at the single point the bridge reads it. Keep verbatim in `toWhere`.
3. **`MEETING_OUTCOME_CLASS` → derived views** (`enums/meetings.ts:84-136`, `outcome-pipeline-map.ts:22`, `derived-pipeline-sql.ts:38`) — one `Record<MeetingOutcome, …>` declaration; sentiment, the three outcome sets, the pipeline map and the SQL CASE all derive from it, so nothing can drift and a new outcome is a compile error until classified. This is exactly the shape the pipeline-reach family (§4) should take.
4. **Set-based scoped mutations** — `moveMediaPhase` (`media-ops.ts:80-92`: `UPDATE … WHERE id IN ids AND scope`, out-of-scope ids match nothing, no per-row probe) and `setHeroImage` (`:101-123`: scoped read authorizes, the project-wide unset is bounded to the proven owner, the target write is scoped again, all in one tx). Replaced two unscoped `db` loops in the router. This is D-16 in miniature: scope lives in the WHERE, not in a probe.
5. **Agent-first precedence in the shareable seam** (`shareable-middleware.ts:35-50`) — a session always wins; a URL token can no longer sideways-grant an authenticated agent a row outside their scope. The ORDER survives the rewrite even though the body does not (C8).
6. **`SystemReason` as a closed, namespaced union** (`system-reasons.ts`) with the rule "adding a variant is a deliberate, reviewable act". The mechanism moves (`.because(reason)` on the rule, D-14) but the idea — every unrestricted path names why — is right, and `contracts.router.ts:224` is the one correct use of it on the branch.
7. **Validated token → actor as ONE function** (`resolveShareTokenActor`) — three hand-rolled `proposal.token !== token` compares became one validated path, and a wrong-proposal token now yields NOT_FOUND instead of UNAUTHORIZED (existence non-leak, documented in its JSDoc). It becomes `bearerActor`, but the shape (validate, then mint a narrow principal) is the CASL JWT cookbook.
8. **`getAccessiblePipelines` as a FORBIDDEN gate at the API** (`customer-pipelines.router.ts:35`) — closing "any agent can request `pipeline:'leads'` directly" was right; only the SOURCE of the list (a mirror) is wrong.
9. **Actor-native feature DALs** (`getCustomerPipelineItems(ctx, pipeline)`, `getCustomerProfile(ctx, id)`, `moveCustomerPipelineItem(ctx, params)`) — the signatures moved from `(userId, isOmni, canSeeUngated, …)` loose booleans to `(ctx, …)`, which is the shape D-16 wants. The bodies are rewritten, the signatures survive.
10. **The `hasNoMeeting`-style discipline that DID NOT happen elsewhere**: the branch authored exactly the operators the rules needed (`participatesViaMeeting`, `inDerivedPipeline`) and only one speculative one (`hasNoMeeting`). Compare with `ScopeOperator.parseValue`/`toJS` and `registeredOperatorNames` — three speculative members that never got a caller. The lesson generalizes: every primitive on this branch with 0 callers (A13, A18, A21, C2) was written "for the next phase".

The cleanest three, cited for the summary: **`interpret` + `ast.ts` + `operators.ts` (the adapter core)**, **`MEETING_OUTCOME_CLASS` and its derivations**, **`moveMediaPhase`/`setHeroImage`**.
