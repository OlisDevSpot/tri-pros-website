## Why this epic exists

Authorization is split across two hand-maintained artifacts that silently drift (spec §1): **CASL** owns the verb (conditionless today), **hand-written `EntityServerSpec.visibility` fns** own the row predicate. Because they're separate, they diverge — producing the live `:367` project drift, the un-expressible manager role, the `LeadsPool` magic flag, and a class of `null`-overload leaks (`meeting-flow.router.ts:40` et al.).

**Thesis:** make CASL rules the single source of truth; **compile** the row-visibility SQL predicate from the rules (`rulesToAST` → ucast AST → Drizzle interpreter), the way `@casl/prisma`'s `accessibleBy` does. See spec §1.

## Design decisions (locked — see spec §2)

The eight approach forks are settled in the spec's §2 table (child inheritance = split; project drift = business ruling; sequencing = per-entity atomic; scope = server core + phone signature; child mechanism = structural `parent`; interpreter = hand-walk, no `@ucast/sql`; operator registration = single `defineScopeOperator`; `ctx` sourcing = spec-threaded, no subject registry). **Do not re-litigate here.** If a phase's implementation surfaces a reason to reopen one, note it in that phase's plan and ping.

## The critical migration invariant (spec §4.1)

**The row predicate lives OUTSIDE CASL today, so this is NOT a behavior-neutral engine swap.** Every current `read` rule is conditionless → compiles to allow-all. The entire risk surface is **false-ALLOW (leak)**, not false-deny. Two rules bind every phase:

1. **No behavior-neutral "engine-only" phase exists.** The engine and the migrated conditions land **together, per entity** (that's why Phase 0 wires *nothing* into production, and Phase 1 is per-entity atomic).
2. **Conditions REPLACE the conditionless verb — never sit beside it.** CASL OR-merges rules; a leftover conditionless `can('read', X)` dominates → allow-all → leak.

## Verification model (no test runner in this repo)

This repo has **no test framework** (no vitest/jest, 4 stray `.test.ts` files, no `test` script). Per the shipped tRPC epic, every slice gates on **`pnpm tsc && pnpm lint` green + manual `EXPLAIN`/equivalence review** — not automated unit tests. This epic follows the same gate. Where the spec says "unit-test the compiler," read: **construct the input by hand in a scratch `tsx` (uncommitted, in the scratchpad), print the compiled SQL / `EXPLAIN` it, and record the evidence in the phase plan's verification log.** The compiler is pure and deterministic, so hand-authored-input → hand-authored-expected-SQL comparison is the equivalence gate.

> If a test runner is later adopted, the compiler + the Phase-1 equivalence assertions + the §11.4 exhaustiveness check are the first things that should become real tests. Tracked as a follow-on, not a blocker.

### Actor-seam conventions (locked — grill 2026-08-18)

Govern every Phase-4 fix and every later cutover. Spec §3/§6/§8/§9 has the actor union + module interfaces; these are the *usage* rulings.

1. **A/B/C classification precedes every fix.** Tag each SYSTEM_CONTEXT/token site: **A** = mis-scoped *user* write (a real `userActor` whose scope was thrown away — e.g. meeting-flow passing `SYSTEM_CONTEXT`); **B** = genuinely privileged write (`systemActor(reason)`); **C** = bearer/single-row gate (`tokenActor`). Mis-classifying is how the original IDORs were born (wrapping A in `systemActor` would *keep* the hole).
2. **Client-supplied id → point-probe; server-derived id → named system write.** (Q6/Q9)
   - Writes + single-row-by-id fetches with a **client-supplied** id: **point-probe `canAccess(spec, actor, id, action)` → throw `NOT_FOUND` on miss** (not FORBIDDEN — don't leak existence), scoped write retained underneath as defense-in-depth. Brings the dead `canAccess` alive.
   - Lists/filters stay **pure scope-threaded** (no point-probe).
   - A **server-derived** id (from an already scope-authorized read — e.g. contracts.age's `proposal.customer.id` after a token-scoped `getFullView`) → **`systemActor(reason)` transitive write.** Invariant: sound *only because* the preceding read is scope-enforced; target must never be client input.
3. **`tokenActor` = scope + subject, NO ability.** Verb-boundary is the *endpoint* (which endpoints accept the token); row-boundary is the scope. `resolveActorScope` branches: user→compile from ability; token→return `actor.scope` verbatim; system→null. One canonical `validate-share-token → tokenActor` path absorbs the 4 hand-rolled `proposal.token !==` checks. **Funnel `leadId` is a `tokenActor`** (`eq(customers.id, leadId)`) — safe because `customers.id` is `defaultRandom()` UUID. **Guardrail: id-as-capability only on random-UUID pks, never `unsafeId` serial.**
4. **`systemActor(reason)` takes a closed namespaced `SystemReason` union** (`webhook:* | sync:* | intake:* | admin:*`), each variant carrying a one-line "why the bypass is safe" comment. The union IS the auditable catalog of every unrestricted write; adding a bypass is a deliberate reviewable act. `SYSTEM_CONTEXT→systemActor` is therefore a *classification per site*, not a find-replace.
5. **Deny-safety: one standalone `requireResolvedScope` helper; `null` = sole deliberate allow-all; `undefined`/absent → throw.** (Q10) Name states the intent: a query may only run once its scope has been REQUIRED to exist (deliberate-`null` vs accidentally-omitted-`undefined` — the two states `?? undefined` silently collapses). Replaces the ~10 hand-written `and(eq(pk,id), ctx.scope ?? undefined)`. `ctx.scope` typed **non-optional** `SQL | null`. Helper stays **standalone** (both current + sub-plan-A's future `create-crud-dal` call it) so deny-safety doesn't deepen the `create-crud-dal.ts` merge seam.

### Procedure reconception: `agentProcedure` → `staffProcedure` (rename, not supersede)

`agentProcedure`'s gate (`ctx.ability.can('access','Dashboard')`) is a **pure gate — adds nothing to `ctx`** (session/ability come from `protectedProcedure`). Requirements accumulated across all 23 consumer files (2026-08-18) established:

- The gate's real load-bearing job is **excluding `homeowner`/`user` accounts** (they hold better-auth logins). Identity-only ≈ `protectedProcedure` → would open staff endpoints to homeowners/leads. So the "is-Tri-Pros-staff" intent is a **real security boundary**, not legacy cruft.
- The CRUD factory (`create-crud-router.ts:80`) is a **single chokepoint** already enforcing per-slot CASL (`assertCan`/`assertCanUpdateFields`) independent of the gate → factory CRUD is safe regardless of the gate name.
- **Decision: rename, not supersede.** `staffProcedure` is semantically identical to `agentProcedure` (same capability gate). **No `@deprecated`, no alias, no coexistence** — rename the definition + sweep all 23 usages in one inert commit (Phase 7). `superAdminProcedure` keeps its name, re-parents to `staffProcedure` (its `manage all` gate is load-bearing — lead-sources/voip global ops + anti-IDOR boundary under SYSTEM_CONTEXT).
- **Gate expression = capability-based, INTERIM.** Keep `can('access','Dashboard')` for now, marked `// INTERIM — not the final gate shape; future is-staff reconception needed`. **YAGNI on a bare `userProcedure`** identity rung — `staffProcedure` extends `protectedProcedure` directly; actor-on-ctx rides in with Phase 5's `ctx.actor`; introduce `userProcedure` only if a genuine sub-staff route appears.
- **Authorization moves into the body + service layer** (services run from backend paths too, so they must carry authz — the procedure can't own it). Procedure answers "who is this user + their scope/ability"; body/service authorizes the operation.
