The bottlenecks, ranked
1
Your review time

About 20 actions across eight branches can only be done by you: iPad checks, copy reads, merge choices, Zoho edits, a TV pairing, two prod schema pushes. Built-to-ready waits ran 6, 10, 20 and 21 days. The iPad isn't always at hand ("no ipad I can test it on for now", 30 Oct).

Fix: one review sitting a day with a prepared queue; screenshots and a check list on every PR; your notes left as comments on the preview, read by that lane's agent; questions on the Decisions tab instead of in a session prompt; lanes small enough to judge in one sitting.

Worktrees alone don't help here. More lanes without this would make the queue longer.

2
Rework after your first look

Proposal v1 was rebuilt as the rework; filter rules FR0 was half reverted the same day (O15); PE4 needed a second round; "Too many bugs to count" on the iPad, 25 Oct. There were 29 plan stress-tests in 23 days, yet the correction still arrived after the build.

Fix: show before building. A screenshot or clickable mock at spec time for any screen change, and a draft PR with a live preview as soon as the first screen works, so a two-minute look happens on day one instead of after the build. Every correction becomes a rule, check or skill edit, so it doesn't recur.

Not a worktree problem.

3
Couplings git can't see

DV3a moves 92 files. The proposal, PE4, home-visit and office-TV branches import moved paths, so they merge cleanly and then fail the type check. On top of that, CONTEXT.md changes on 7 of 8 held branches and the meeting overview card on 5, and the list of merge follow-ups between epics keeps growing.

Fix: a collision check that trial-merges each pair and type-checks the result; a fixed merge order; short-lived lanes; union merges for glossaries; live status kept off shared files.

Worktrees help only partly; long-lived worktrees make the drift worse.

4
Schema reaches prod by hand, one change at a time

There is no migrations baseline yet. The HV release is a five-step sequence (additive push, script, deploy, script, destructive push), and office TV needs your db:push:prod before merge.

Fix: the migrations baseline (plan Tasks 9–10), so prod applies migrations during its build; one schema-owning lane per area; Neon's schema diff posted on the PR.

Neon copies isolate dev but don't order prod.

5
One machine

WSL crashed on 4 Nov, the scene's visual pass took the machine down on 8 Nov, two lanes clash on port 3002, and only you start dev servers.

Fix: review on Vercel previews, not local dev servers. Lanes verify with type-check, lint, tests and screenshots of the preview, and a local dev server runs only for the lane you're shaping with an agent.

More worktrees make this worse unless review moves to previews.

6
Losing the thread

About 1,015 messages from you, 114 compactions and 17 clears in three weeks. "Plans just get lost" (3 Nov). "I am not sure why another session is working on it" (30 Oct). "I don't understand what is going on anymore" (9 Nov).

Fix: this board as the one place for state. Every lane session reads its row at start and writes it at each step, and a resumed session starts from the row, not from memory.

7
Branches still on old main

Both trade-scene branches and #285 carry old main's history (600+ commits over prod). Each scene release needs the file-copy script, and the layout lab can't merge prod directly (43 add/add conflicts).

Fix: re-cut each onto prod once, as the drain did for the others.

What other developers use, checked against our rules

Two facts change several verdicts. The repo is still public and user-owned, so GitHub's merge queue isn't available to it. Making it private (plan Task 1) also ends the free tiers some review bots give public repos.

What the people running many agents say

Review is the ceiling. Armin Ronacher now starts fewer parallel agents, because "it's only so much my mind can review". Simon Willison parallelises research, maintenance and well-specified tasks, the kinds that don't pile up review.

Fix the harness, not the instance. Mitchell Hashimoto turns every agent mistake into a rule or a script so it never recurs. Every's compound loop ends each piece of work by writing its lesson back.

Land one change at a time. Steve Yegge's 20-agent setup still funnels everything through a single merge step. Our version: one merge button, a merge order, and "up to date" required.

Independent review, told what to ignore. Anthropic's guidance: a reviewer with read-only tools or a fresh session, told to skip style, or it always finds something.
